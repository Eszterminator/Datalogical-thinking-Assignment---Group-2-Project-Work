Planning process: Pseudocode

The first step in our algorithm design was thinking about the problem we wanted to solve: recommending books to users based on their genre preferences and time limitations. We considered what data we would need to answer these questions:

  • book genre
  • book title
  • book author
  • average Goodreads rating of the book
  • unique identifier for the book to keep us right
  • page number
  • user's required genre
  • user's speed of reading (in a consistent measurement unit: days)
See the details of researching and finding a dataset here: Dataset

Next, we broke the algorithm down into smaller steps, to understand the logic behind it:

  1. Get user input for genre and speed of reading
  2. Select all the books from the dataset that are in the user's requested genre
  3. Sort the selected list of books by the average rating, in descending order
  4. Add the attribute of "How many days it would take to read the book" by dividing the page number by the speed of rating
  5. Display the top 10 books by ratings in the chosen genre with their respective user-specific reading durations

After breaking the problem down, we wrote pseudocode instructions following the steps above.

Decisions made

  • Upon discussion, we came to the conclusion that leaving the genre question open to the user "Which genre would you like to read?", in order to be able to select at least 10 books in whatever genre they specify would require a very large dataset, that would exceed the scope of this project. Therefore, we decided to limit the genre choices to 4 (Fantasy, Fiction, Classics, Young Adult), to keep the dataset manageable.
  • The genres were selected based on the available data, filtering and counting the books under each genre category in dataset using spreadsheet software in-built functions. We picked the 4 genres that had the most books available in them, to be able to check the reliability of our top 10 selections. At this stage of the project, the algorithm can recommend books from a limited number of genres, however, we recommend for future development of the project extending the dataset and adding more options for the user.
  • For the sorting step described above, we opted for a selection sort algorithm, since we only needed the first 10 highest rated books. This was, we could stop the algorithm after the first 10 biggest rated books were found, making it faster and more efficient than sorting through the whole list of books, as a bubble sort algorithm would have done.

At this stage, we discussed that we could further develop the algorithm, and brainstormed for some further instructions. We decided to add a timelimit element to the book recommendations:

  1. The user would be asked how much time they have available for their next book, and we would filter and display the books from the previously recommended top 10 list that fit into this timeframe.
  2. If none of the books could be read under the given days at the specified speed, we would display a message "None of the top 10 rated books in the specified genre can be read in the specified time, would you like to see recommendations for lower rated books that can be read in ...(insert variable) days?".
  3. Then, if the user inputs YES, we would filter through the full list of books in the specified genre to check which ones fit the timeframe and display them, sorted by highest rated.
  4. If the user says NO, the algorithm would revert to the original step, of inputting a genre.
